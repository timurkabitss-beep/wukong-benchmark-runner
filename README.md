# Wukong Benchmark Runner

Консольное приложение на C# (.NET 8, Windows), которое автоматически дважды прогоняет
**Black Myth: Wukong Benchmark Tool** (Steam, AppID 3132990): CPU-проход и GPU-проход.
Затем оно собирает характеристики ПК и FPS-метрики и сохраняет отчёт в TXT и JSON.

## Требования
- Windows 10/11, .NET 8 SDK
- Steam, установленный Black Myth: Wukong Benchmark Tool (запущенный хотя бы раз вручную до главного меню,
  чтобы он создал `GameUserSettings.ini`)
- **PresentMon 1.x** (консольная версия, например 1.10.0) в файле `tools\PresentMon.exe`
  (скачать: https://github.com/GameTechDev/PresentMon/releases). Нужен для измерения FPS.
- Запуск от имени администратора (требуется PresentMon; манифест запросит права сам)

## Запуск
```
dotnet run -c Release
```
или соберите `dotnet build -c Release` и запустите `bin\Release\net8.0-windows\WukongBenchmark.exe`.
Не трогайте мышь и клавиатуру во время тестов (~2 x 3-4 минуты): программа нажимает клавиши в окне бенчмарка.

Результаты: `Results\<дата-время>\report.txt`, `report.json`, сырые CSV PresentMon и копия исходного ini.

## Как это работает
1. Находит установку через реестр Steam, `libraryfolders.vdf` и `appmanifest_3132990.acf`.
2. Делает резервную копию `b1\Saved\Config\Windows\GameUserSettings.ini`.
3. Для каждого прохода: записывает настройки в ini, запускает `b1_benchmark.exe`, ждёт окно, стартует PresentMon,
   нажимает клавиши из `UiSteps` (config.json), ждёт `BenchmarkDurationSec`, останавливает PresentMon и закрывает игру.
4. Из CSV берутся кадры процесса `b1*` после прогрева (`WarmupTrimSec`), считаются avg/min/max FPS и 1% / 5% low.
5. Параллельно замеряется средняя загрузка CPU и GPU, чтобы подтвердить характер каждого теста.
6. Исходный ini восстанавливается (даже при ошибке).

## Выбор настроек
| | CPU-тест | GPU-тест |
|---|---|---|
| Разрешение | 1280x720 | родное разрешение монитора |
| sg.ResolutionQuality (render scale) | 50 | 100 |
| Качество графики (sg.*) | минимум (0), кроме дальности прорисовки (3) | максимум (4) |
| Трассировка лучей | выкл. | максимум |
| Апскейлеры (DLSS/FSR/XeSS) | не используются | не используются |
| VSync | выкл. | выкл. |

**CPU-тест.** Низкое разрешение и render scale 50% резко снижают число пикселей для видеокарты, поэтому
кадровая частота упирается в процессор. Тени, GI, отражения и RT выключены, это самые тяжёлые для GPU эффекты.
Дальность прорисовки оставлена повышенной: больше объектов в кадре означает больше работы процессора
(отсечение, подготовка draw calls), а на 720p это почти не добавляет нагрузки на GPU.

**GPU-тест.** Родное разрешение, render scale 100% и максимальные качества с трассировкой лучей дают наибольшее
число пикселей и самые тяжёлые шейдеры. Апскейлеры выключены намеренно: они рендерят в меньшем разрешении
и снижали бы нагрузку на видеокарту. VSync выключен, чтобы FPS не ограничивался частотой монитора.

Подтверждение: в отчёте для каждого прохода выводится средняя загрузка CPU и GPU. В CPU-тесте ожидается
заметно более низкая загрузка GPU, чем в GPU-тесте.

## Что нужно откалибровать на своём ПК
- `UiSteps` и `StartupWaitSec` в `config.json`: последовательность клавиш зависит от интерфейса стартового экрана.
  Если бенчмарк не стартует сам, поменяйте клавиши/задержки (поддерживаются Enter, Esc, Space, Tab, стрелки).
- `BenchmarkDurationSec`: должна быть чуть больше длительности сцены. Измерьте секундомером при первом ручном прогоне.
- Имена ключей ini: `sg.*` и ключи разрешения проверены по описаниям пользователей; если какой-то параметр не влияет,
  измените его в интерфейсе бенчмарка, сравните ini до/после и поправьте `Profiles.cs`.

## Ограничения
- Benchmark Tool, насколько известно, не сохраняет FPS в файл (итог показывается на экране), поэтому FPS
  считается независимо через PresentMon по реальным кадрам. Значения могут немного отличаться от цифр на итоговом экране.
- Загрузка GPU суммируется по счётчикам «GPU Engine» (3D) всей системы.
